## Explicit provisional interfaces

- A snapshot consumes frozen validated WorldLayout/CatalogLayout values, never resource files. Operational instance usability and point availability/occupancy are explicit inputs, not persisted new fields. `default` state is usable absent an override; other catalog-declared states require explicit usability. Unknown states/references, duplicate overrides, negative/excess occupancy and inconsistent transformed geometry are malformed, not an empty candidate result. Closed-region objects are never candidates; open-region metadata is revalidated with the existing catalog builder. The canonical access mask is derived internally, never accepted from the caller.
- Requirements are any-of nonempty all-of capability groups, versioned with the existing Activity enum. Room tiers follow §M/T6: sleep bedroom, rest living, write studio, idle/walk Hall; read library/living only; observe system/studio only; think living/library/other. These are room-kind rules, never type/instance rules.
- Current-point stickiness is a binary exact instance/point identity match, extending legacy continuation-in-place semantics without broadening destinations. A preference is a binary explicit point association with an existing accepted long-term preference Memory. Candidate/rejected/archive memories cannot grant a bonus; no text parsing, stored keys, inferred preference or promotion. Task targets do not name furniture. Task scoring beyond this explicit accepted-preference hook remains deferred.
- Decision context supplies immutable RngState and the number of preceding draws in this decision. A private RngStream uses `decision_counter + 1`, matching `core.direction.decision_rng`; it skips those draws and consumes one randint only when multiple minimum-score candidates tie. Output reports 0/1 draws for the future caller; no stream/counter/global state is mutated. Canonical tie order is `(instance_id, point_id)`. Allowed-activities and S9 checks draw nothing.
- Resolver position is a validated canonical Tile. It never rounds a fractional position or creates movement/action state. R1A-05 supplied-time mid-edge rerouting remains the later action consumer's responsibility, with no change to its no-snap semantics. Resolver routes are grid routes; no live movement integration is claimed.
- Saved-layout S9 validation starts from the validated canonical safe tile and first applies existing safe-layout checks. Runtime temporary unavailability returns `no_candidate` and omits the activity; saved-layout coverage failure raises an S9 error. Neither invokes recovery or bypasses placement prevention.
