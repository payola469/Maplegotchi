## Resolved decisions and implementation contracts

STEP 103 resolved blocked/invalid-source recovery. STEP 104 replaces the ambiguous fixed K4 corridor with dynamic connectivity. K1 door clearances (including closed doors), K2 resolved approaches and K3 Hall rows remain exact protected cells. K4 requires all open walkable cells, open-door access and required approaches in one orthogonal component, containing the canonical safe tile and Maple when her position is supplied. A proposed furniture change may obstruct a direct route only if an alternative survives. No approach-row endpoint or fixed route is inferred.

`derive_walkability(world, catalog)` consumes validated `WorldLayout`/`CatalogLayout` values, reusing catalog-transformed blocking tiles. Its canonical frozen tuples expose permitted cells, blockers, walkable cells, protected cells, required approaches, open-door access and components. It intentionally derives unsafe candidate masks so validation can diagnose them and emergency recovery can inspect exceptional state. `validate_safe_layout(world, catalog, maple)` rejects unsafe proposals with deterministic S-rule errors; callers must supply Maple's position to validate her location. R1A-07 will call this boundary before placement acceptance. It does not execute placement or invoke recovery. Open doors with closed-region endpoints are rejected (S5), rather than allowing accidental closed access.

`recover(mask, Position)` returns immutable `RecoveryResult` and optional `Relocation` with fixed kind `maple_relocated`, original integer coordinates, destination Tile and enum reason: `blocked_source`, `no_reachable_candidate`, or `invalid_source`. `Position` permits exceptional out-of-grid integers while ordinary Tile remains grid-validated. A valid current tile returns no event. For a blocked permitted source, every valid adjacent walkable cell is already a candidate, so the first nonempty BFS layer is terminal; row/column sorting selects the nearest tie without traversing another blocker. Invalid sources never seed traversal. Fallback requires the declared canonical marker, walkability and keep-clear protection; otherwise `unsafe_fallback` returns no destination/event. No relocation event is persisted.
