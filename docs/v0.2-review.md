## 2. What v0.2 autonomy adds

- **Room and movement (A1, ADR-0027):** named interaction points; Maple walks to a
  destination before an activity starts; position/path derived from `now`; new `sofa`,
  `think` activity; Writing Desk ≠ Computer Desk.
- **Goals and priority (A2, ADR-0026):** 16 goal types, 30–120 min horizon;
  priorities critical/high/normal/low; critical needs interrupt and resume the
  suspended goal; Greet/Pet never interrupt.
- **One life-event model (A3, ADR-0028):** append-only `decision`, `action_event`,
  goal events; SSE `life`/`movement`; `/api/life-events` catch-up.
- **AI Director (A4, ADR-0026):** a proposal (goal, action, duration, one reason) is
  validated, clamped or rejected by core; any failure → rule direction. Called outside
  the writer lock; the heartbeat never calls it. No chain-of-thought is stored.
- **Reader/writer (A5, ADR-0029):** reads only an allowlisted catalog by id; writes
  only documents into maple.db (no new filesystem path); `tool_use` provenance.
- **Memory (A6, ADR-0030):** short-term (~36 h) → archive unless promoted; preferences
  need evidence on 3 days or confirmation; ≤ 5 memories given to a Director/writer.
- **Daily Reflection (A7, ADR-0031):** once per Maple day; summary, memories,
  preference evidence, tomorrow's intent; never changes needs.
- **Room UX (A8):** speech bubble from real state, furniture hotspots, live feed,
  owner Inspector (decisions, memory, documents, reflections).
- **Discord (A9, ADR-0032):** separate `maple-discord` service holds the bot token;
  token-guarded idempotent `POST /api/conversation/messages`; replies from real state
  (rule or validated `/reply`); slash commands read-only.
- **Brain companion (A10, ADR-0033):** `maple-brain` on 127.0.0.1:8471 with
  `/generate`, `/decide`, `/reply`, `/health`; provider is configuration only.

Unchanged: Greet/Pet limits (D14), 300 s heartbeat, read-only senses, no subprocess in
Maplegotchi, loopback bind + Tailscale Serve, security headers, single writer.

## 3. Database migrations (v3 → v9, forward-only, automatic at start)

| v | Change |
|---|---|
| 4 | Rebuilds `life_state`, `timeline_event`, `journal_entry` for activity set v2 + movement; new append-only `goal`, `decision`, `action_event`. Verified in-transaction. **A verified copy is written to `/data/maple/pre-migration/` first; if that fails, nothing migrates.** |
| 5 | `life_state.critical_since` (critical interruption tracking) |
| 6 | `life_state.task_*` columns; append-only `document`, `tool_use` |

All run in one start-up; identity, `born_at`, seed and v3 history are preserved.
A pre-v4 release cannot open a v9 database (`SchemaTooNewError`); going back means
restoring a v3 copy (§7, R6).

## 4. API and event changes (all additive)

New `GET`: `/api/room`, `/api/decisions`, `/api/life-events?after_revision=`,
`/api/documents`, `/api/documents/{id}`, `/api/memory`, `/api/memory/search`,
`/api/reflections`, `/api/conversation`.
New `POST`: `/api/conversation/messages` — gateway only (Bearer
`MAPLE_GATEWAY_TOKEN`, no `Origin`, ≤ 8 KB); 404 when no token is configured.
Snapshot additions: `activity.{phase, point, furniture, pose, facing, position, route,
task}`, `goal`, `suspended_goal`, `action_priority`, `bubble`, `director`.
SSE: new `movement` and `life` events (existing `snapshot`, `heartbeat`,
`observations`, `interaction`, `journal`, `timeline` unchanged).
Life-event types: `docs/api.md` → "Life events".

## 6. Deployment order (owner-run)

**P. Pre-deployment checks (read-only)**
1. `readlink /opt/maplegotchi/current` → record the current SHA (the rollback target).
2. `sudo /usr/local/sbin/maple-db-snapshot stage --source /data/maple/maple.db --dest /root/maple-pre-<new-sha>.db`
   → `integrity=ok`, `user_version=3` expected. Keep this file until v0.2 is accepted.
3. `df -h /data /opt /root` — room for the release (~venv) and 2× `maple.db`.
4. `systemctl is-active maplegotchi personal-ai-monitor.timer paolo-core-backup.timer`;
   last nightly backup succeeded.
5. Old bridge: `ss -ltnp | grep 8471` → its unit/process; record its exact provider
   command, model and login location; record current `MAPLE_BRAIN*` in maplegotchi.env.
6. `python3 /opt/maplegotchi/current/deploy/verify/check_boundaries.py` → baseline.
7. `cp -a /etc/maplegotchi/maplegotchi.env /root/maplegotchi.env.pre-v0.2`.

**A. Build (trusted machine)** — `scripts/check.sh` green, then
`scripts/build_release.sh <sha>`; copy bundle + sha256 to paolo-core.

**B. Maple v0.2, AI still on rules**
1. `install_release.sh <bundle> <sha256> <uv>` (does not touch the running Maple).
2. Make sure `MAPLE_DIRECTOR`/`MAPLE_REPLIER` are absent (rule). `MAPLE_BRAIN` may stay
   as it is (the old bridge serves `/generate`).
3. `activate_release.sh <sha> --allow-migration`; `systemctl restart maplegotchi`.
4. Verify: `journalctl -u maplegotchi` clean start; the pre-migration copy exists:
   `ls /data/maple/pre-migration/`; `/api/status`; UI loads via Tailscale; Greet/Pet;
   `check_boundaries.py` passes; after ≥ 1 heartbeat, restart continuity;
   `maple-db-snapshot stage …` → `integrity=ok user_version=9`.
5. Let it run for a few hours on rules (heartbeats, decisions with `rule_director`).

**C. maple-brain replaces the hand-made bridge** (`deploy/brain/README.md`)
1. Create `maple-brain-svc`, install from `/opt/maplegotchi/releases/<sha>`, env file
   with `MAPLE_BRAIN_PROVIDER=none` first, unit installed, `systemd-analyze verify`.
2. Provider login as `maple-brain-svc` (into `/var/lib/maple-brain`).
3. Set `MAPLE_BRAIN_PROVIDER=command`, `MAPLE_BRAIN_COMMAND`,
   `MAPLE_BRAIN_MODEL=gemini-3.8-flash-medium`.
4. Stop + disable the old bridge (keep its files); `systemctl enable --now maple-brain`;
   `curl -s 127.0.0.1:8471/health`.
5. Verify: loopback-only listener; no `/data/maple` access; MDWE `no` only here.

**D. Enable AI on Maple's side, one switch at a time** — restart after each and watch:
`MAPLE_BRAIN=antigravity` (journal) → `MAPLE_DIRECTOR=antigravity` (`/api/decisions`
shows `accepted`/`clamped`, fallbacks are explained) → `MAPLE_REPLIER=antigravity` after E.

**E. maple-discord** (`deploy/discord/README.md`) — bot + intents, account, install
from the release, credentials, ids, `MAPLE_GATEWAY_TOKEN` in maplegotchi.env, restart
Maple, enable `maple-discord`; verify replies, 401 without token, other users ignored.

**F. Close-out** — `check_boundaries.py`, `sandbox_probe.sh`, Tailscale Serve status
(Funnel off), one nightly backup with `user_version=9` and a test restore.

## 7. Rollback and recovery

| Situation | Action | Data |
|---|---|---|
| Before B.3 | nothing active changed; remove the unused release if wanted | untouched |
| Migration refused at start (pre-migration copy failed) | Maple did not migrate; `activate_release.sh <old-sha>` + restart; investigate disk/permissions | untouched (v3) |
| v0.2 misbehaves, AI-related | set `MAPLE_DIRECTOR` / `MAPLE_REPLIER` / `MAPLE_BRAIN` back to `rule`, restart | continues |
| v0.2 bug in core | prefer a forward-fix release on schema 9 (same-schema activation + restart) | continues |
| Must run the old release again | R6 restore in `deploy/install.md` with `/root/maple-pre-<sha>.db` or `/data/maple/pre-migration/maple.v3.*.db`; restore `/root/maplegotchi.env.pre-v0.2` | **loses life since migration** (kept in quarantine) |
| maple-brain fails | Maple falls back to rules automatically; `systemctl disable --now maple-brain`, re-enable the old bridge if wanted | continues |
| maple-discord fails / unwanted | `systemctl disable --now maple-discord`; remove `MAPLE_GATEWAY_TOKEN`, restart Maple (endpoint → 404) | continues |
| Companion release bad | point `/opt/maple-{brain,discord}/current` at the previous release, restart | none involved |
| Backup | patch unchanged by v0.2; `deploy/backup/README.md` → Rollback | restic history kept |
